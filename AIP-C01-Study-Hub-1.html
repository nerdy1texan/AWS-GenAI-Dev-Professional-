Optional primer

GenAI foundations the exam assumes

Skim this if you already work with LLMs; the exam is not testing deep model-training theory.

Foundation models vs traditional ML

For this exam, think integration more than training. FMs are general-purpose models exposed through managed or hosted inference. Your job is to choose, invoke, ground, govern, observe, and optimize them. Training algorithms and feature engineering are explicitly out of scope.

Tokens and context windows

Cost, latency, truncation, caching, and retrieval design all depend on tokens. Input tokens include system instructions, conversation history, retrieved context, tool schemas, and user content. Output tokens are generated completion. Context overflow is an application failure mode, not merely a model limitation.

Embeddings and vector search

Embeddings map content to vectors so semantic similarity can be computed. RAG retrieves relevant chunks, optionally reranks them, and supplies evidence to the FM. Always separate retrieval quality from generation quality when debugging.

RAG mental model

Ingest → parse → chunk → embed → index → retrieve → filter/rerank → augment prompt → generate → cite/evaluate. Each stage can independently fail, drift, add latency, or leak data.

Agentic AI mental model

An agent is a model-driven control loop with tools, state/memory, policies, stop conditions, and observability. Production agents need deterministic boundaries around nondeterministic reasoning.

Sampling controls

Lower temperature/top-p is usually preferred for deterministic extraction, policy, and structured output. Higher variability can help creative generation. Do not treat sampling as a substitute for grounding, evaluation, or schema validation.

What you must know

Exam traps

“Use the biggest model.”Wrong default. Professional-level questions reward a measured quality/latency/cost/compliance tradeoff.
“Fine-tune first.”RAG or prompt changes are often lower-risk and cheaper; customize only when evaluation shows persistent behavior/domain gaps.
“Vector DB = all data.”Keep source-of-truth data and metadata governance separate. Vector indexes are retrieval structures, not your authoritative data system.
“More chunks always improve answers.”More retrieved text can increase noise, latency, and token cost. Tune top-k, filters, chunking, and reranking with evaluation.

Implementation and Integration

Blueprint-aligned notes with exam traps and service vocabulary.

Blueprint tasks

2.1 · Agentic AI & tools2.2 · Deployment strategies2.3 · Enterprise integration2.4 · FM APIs2.5 · Application integration & developer tools

What you must know

Exam traps

“Agent for every workflow.”Use agents for dynamic planning/tool choice. Use deterministic orchestration when the workflow is known and correctness/auditability dominates.
“Lambda for any agent.”Lambda is great for short stateless tools; long-running/stateful/heavy agents may fit AgentCore Runtime, ECS, or EKS better.
“Retry every failure.”Model throttling may be retryable; validation, auth, malformed schema, and deterministic tool errors are not fixed by blind retry.
“Tool schema is just documentation.”Tool definitions are part of the control plane. Validate parameters server-side and authorize each operation independently of the model.

AI Safety, Security, and Governance

Blueprint-aligned notes with exam traps and service vocabulary.

Blueprint tasks

3.1 · Input/output safety3.2 · Data security & privacy3.3 · Governance & compliance3.4 · Responsible AI

What you must know

Exam traps

“Guardrails replace IAM.”Guardrails control content; IAM controls resource access. Use both.
“Log everything for observability.”Prompt/response logs can contain secrets/PII. Minimize, protect, mask, retain intentionally, and restrict access.
“Encryption solves privacy.”Encryption is necessary but does not address overcollection, improper access, retention, prompt leakage, or unauthorized retrieval.
“RAG eliminates hallucinations.”Grounding lowers risk. You still need retrieval evaluation, citations, confidence/abstention, and output validation.

Blueprint tasks

What you must know

Exam traps

“Provisioned Throughput is always cheaper.”It trades commitment/capacity for predictable throughput. Compare utilization and demand shape.
“Streaming reduces model compute.”Streaming improves time-to-first-token/user perception; it does not inherently reduce total generation cost.
“Cache all responses.”Cache only when semantics, authorization scope, freshness, and privacy make reuse safe.
“CloudWatch metric = quality metric.”Operational telemetry does not automatically measure factuality, relevance, helpfulness, or task success.

Blueprint-aligned notes with exam traps and service vocabulary.

What you must know

Exam traps

“One benchmark selects the best model.”Use representative workload datasets and evaluate quality, safety, latency, and cost together.
“LLM-as-a-judge is ground truth.”It scales evaluation but can be biased/inconsistent. Calibrate against human-labeled examples.
“Fix hallucinations by raising temperature.”Temperature changes variability; grounding, retrieval, prompts, and verification address factuality.
“End-to-end score tells you root cause.”Decompose retrieval vs generation vs tools so you know what to change.

Pattern library

Architecture patterns to be able to reason about

These are not “one right architectures”; they are decision frames for exam scenarios.

Production conversational assistant

CloudFront/Amplify → Cognito → API Gateway → Lambda/AgentCore Runtime → Bedrock ConverseStream → Guardrails → response. Persist session state in DynamoDB only when needed. Send operational metrics to CloudWatch; selectively enable invocation logging with privacy controls.

Choose it when: Use when interactive latency, auth, streaming, and controlled session state are the priority.

Enterprise RAG

S3/Confluence/SharePoint → parsing/BDA → chunking → embeddings → Knowledge Bases/vector store → metadata filtering → hybrid retrieval → reranker → FM → citations/guardrails. Evaluate retrieval and generation separately.

Choose it when: Use when answers must be grounded in enterprise documents with source attribution.

Secure tool-using agent

Client → AgentCore Gateway → AgentCore Runtime/Strands → AgentCore Memory → tools (Lambda/APIs) with Identity/IAM → Observability/Evaluations. Put policy checks and human approval before irreversible actions.

Choose it when: Use for dynamic multi-step work where the model chooses tools, but actions must remain governed.

Deterministic GenAI workflow

API/EventBridge → Step Functions → validation Lambda → Bedrock → post-processing → human approval → downstream system. Use retries and compensating actions where appropriate.

Choose it when: Use when the sequence is known and auditability/reliability matters more than autonomous planning.

Async document pipeline

S3 event → EventBridge/SQS → Step Functions → BDA/Textract/Bedrock → structured validation → storage/index → notification. DLQ captures poison jobs.

Choose it when: Use for bursty, long-running document/media processing where synchronous APIs are fragile.

Multi-model router

Stable application API → routing layer (rules/AppConfig/metrics or Bedrock prompt router) → selected FM/inference profile → common response normalization → telemetry.

Choose it when: Use to optimize quality/cost and reduce provider lock-in while retaining a stable application contract.

Resilient multi-Region inference

Application in home Region → Bedrock cross-Region inference profile → available destination Region(s). Keep data-residency requirements explicit; use fallback/degraded mode for dependencies that do not support the same routing model.

Choose it when: Use for higher throughput/availability or Region-constrained model availability.

GenAI CI/CD quality gate

Git → CodePipeline/CodeBuild → unit/security tests → prompt/RAG/agent evaluation dataset → thresholds → canary deploy → monitor → automatic rollback on quality/latency/error regression.

Choose it when: Use to prevent “prompt-only” changes from bypassing normal software release controls.

Hands-on

20 production-style labs

Each lab is deliberately tied to a likely architecture decision, not console-click memorization. Use a sandbox account and clean up resources.

Cost hygiene: set a small AWS Budget, use a sandbox account, prefer on-demand/serverless while learning, and delete knowledge bases, vector indexes, endpoints, log retention, and provisioned resources after labs.
Lab 1

Bedrock Converse baseline

BedrockAWS SDKCloudWatch

Create a minimal chat client using Converse; capture token usage, latency, stop reason, and request ID. Add ConverseStream and compare time-to-first-token.

Exam angle

Explain why Converse reduces model-provider-specific request code.

Lab 2

Model routing abstraction

LambdaAPI GatewayAppConfigBedrock

Build one stable `/generate` API. Put model ID and routing threshold in AppConfig. Route simple vs complex prompts, then change models without redeploying business logic.

Exam angle

Dynamic model selection and provider switching.

Lab 3

RAG from S3

S3Knowledge Basesembeddingsvector store

Create a small document corpus, ingest it, query with RetrieveAndGenerate, inspect citations, then intentionally add a stale/conflicting document.

Exam angle

Understand ingestion, embeddings, retrieval, grounding, and freshness.

Lab 4

Chunking experiment

Knowledge BasesS3

Index the same content with two chunking strategies. Build 20 questions and compare hit relevance, answer faithfulness, latency, and tokens.

Exam angle

Chunking is an empirical retrieval choice.

Lab 5

Hybrid search + reranking

Knowledge Bases/OpenSearchreranker

Create queries with exact product/error codes plus semantic wording. Compare semantic-only, hybrid, and reranked top-k.

Exam angle

When lexical signals matter and how reranking changes precision/cost.

Lab 6

Metadata security filter

Knowledge Bases/vector storeIAM

Tag documents by department/tenant. Enforce retrieval filters from authenticated user claims; test cross-tenant attempts.

Exam angle

Authorization must happen before generation.

Lab 7

Prompt governance

Prompt ManagementS3CloudTrail/CloudWatch

Create parameterized prompt versions, test a breaking change against a golden dataset, and record the promoted version.

Exam angle

Treat prompts as versioned release artifacts.

Lab 8

Guardrails defense in depth

Bedrock GuardrailsLambda

Configure denied topics and sensitive-data filtering. Add app-side schema validation and tool authorization. Test prompt injection and data-exfiltration attempts.

Exam angle

Guardrails + IAM + validation, not guardrails alone.

Lab 9

AgentCore Runtime/GatewayStrandsLambda

MCP/tooling, runtime, gateway, and observability.

Lab 11

SQSStep FunctionsBedrockDLQ

Last-mile review

Exam cheat sheet

Print this section or use browser Print → Save as PDF.

Bedrock API chooser

  • Converse: common chat interface across supported models.
  • ConverseStream: interactive streaming.
  • InvokeModel: direct/model-specific control and non-chat use cases.
  • Async architecture: queue/state machine for long or bursty work.

RAG chooser

  • Poor exact-keyword recall → hybrid search.
  • Too much noisy context → filters/top-k/reranker.
  • Multi-part question → query decomposition.
  • Missing nearby qualifiers → hierarchical/structure-aware chunking.
  • Stale answer → sync/freshness, not “bigger model.”

Agent vs workflow

  • Unknown/dynamic plan and tool choice → agent.
  • Known steps, approvals, retries → Step Functions.
  • Short stateless tool → Lambda.
  • Longer/heavier agent/tool server → AgentCore Runtime/ECS/EKS.

Security stack

  • IAM least privilege for resource/action authorization.
  • Guardrails for content/sensitive data/policy controls.
  • KMS for encryption; Secrets Manager for credentials.
  • PrivateLink/VPC endpoints for private connectivity.
  • CloudTrail for audit; invocation logs for model I/O only when appropriate.

Cost levers

  • Smaller model or model tiering/routing.
  • Prune/summarize context and conversation history.
  • Reduce top-k; filter/rerank better.
  • Prompt caching for repeated long prefixes.
  • Cap output tokens.
  • Measure cost per successful task, not per API call only.

Latency levers

  • Streaming for time-to-first-token.
  • Parallelize independent calls.
  • Use caching/precomputation when freshness permits.
  • Optimize vector index/query/top-k.
  • Use appropriate inference profiles/capacity.

Evaluation ladder

  • Unit/schema/security tests.
  • Golden prompt dataset.
  • Model quality + latency + cost.
  • Retrieve-only RAG evaluation.
  • End-to-end RAG faithfulness/citations.
  • Agent task/tool evaluation.
  • Canary/shadow + production KPI monitoring.

Troubleshooting order

  • Auth/request format
  • FM/API/throttling
  • Prompt + context window
  • Retrieval freshness/chunk/embed/filter
  • Tool schema/permissions/errors
  • Output validation
  • Downstream integration

Professional-exam answer filter

  • Meet every stated requirement.
  • Prefer managed service when it fully satisfies needs.
  • Use least privilege and explicit governance.
  • Prefer decoupled/resilient patterns.
  • Choose the simplest architecture that meets requirements—avoid solving unstated problems.

Volatile facts — verify before exam

  • Supported models and Regions
  • Pricing and quotas
  • AgentCore/MCP capabilities
  • Knowledge Base vector-store options
  • Prompt caching limits
  • New/renamed AWS services
